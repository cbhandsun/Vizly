## 长度、空白与自动决策

一份需求分配保存重载证据中，global 流向长度5351.5，compact 为3891.5，差1460；紧凑模式增加7条跨域回移、总回移12476。当前算法扣除新增回移后选择global。代码 `domainDagreLaneRankDecision.ts` 还使用节点中位尺寸加间距形成迟滞范围，并允许手动覆盖。

上述场景约97.0%/95.9%的“空白率”是业务节点矩形并集与泳道总面积之比，不包含连线路由所需空间。不能据此认定97%的面积是算法冗余，也不能把当前评分权重当成行业标准。

- 必要长度：全局阶段顺序、节点尺寸、端点净距、跨域移交及合法反馈通道共同形成的长度。
- 算法冗余：无依赖子域被强制串行、重复容器约束、缺失合理候选导致的绕行；已修复部分，孤立节点排列仍有优化空间。
- 视图问题：业务步骤很多且跨度不均衡时，保持等尺寸约束下必然有稀疏域。需要折叠/分段视图评估，而不是独立裁切每条泳道。

### 补充源码核对：长标题编辑与尺寸（2026-09-05）

`useCustomNodeInteractions.ts:38` 的编辑保存更新 `description` / `label`，并调用节点更新接口或 `setNodes`；该 Hook 本身没有重算宽高。`CustomNodeGraphics.tsx:142` 的编辑 textarea 使用完整 `editText`，但固定容器内的可视读取仍需真实交互验证。因此现有证据支持“文字数据保留、显示可能裁切”，不支持“内容丢失”，也不证明上层节点更新服务不会重算尺寸。下一步只检查上层更新尺寸契约与真实编辑读取，避免扩大到所有节点渲染器。

补充尺寸链路：`hooks/useDesignerBatchUpdates.ts:43` 的 `updateNodesBatchCore` 只合并显式 style/data/theme/position，并同步选中节点；没有针对 description 更新的尺寸测量。`useCustomNodeStyleResolution.ts:295` 外框设置 overflow:hidden；文字容器为100%高度。这与固定尺寸长标题截图一致。修复验收应覆盖固定尺寸下的完整读取入口，以及编辑保存后尺寸/路由不意外改变；若引入自动扩高，必须作为几何变更验证，不能只增加CSS换行。
