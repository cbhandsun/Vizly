# 层级契约升级与历史文档兼容

## 配套版本

层级契约首次验收时的历史配套记录为 `@vizly/core@0.1.0-alpha.9` 与
`@vizly/contracts@0.1.0-alpha.3`；这不是当前候选或已部署网站的版本声明。
Core 对 contracts 使用精确版本依赖。

核对当前网站选择时，同时检查 `package.json` 中的依赖、`package-lock.json`
对应记录、`vendor/` 中实际 tarball 的 SHA256，以及已安装包的内容。
已部署网站还须核对对应部署凭据中的源码和 SDK 哈希，不能从本地配置推断线上版本。
应用自身版本号以 `package.json` 为准。Core 和 contracts 的版本号不要求相同；
升级时必须保证所需公开导出兼容，并通过安装包及网站回归。
本地 tarball 交付不表示该版本已发布到 npm。

不要只替换 Core 包而保留 registry 上的旧 contracts。新增恢复入口直接调用
`importLegacyVizlyDocument`，旧 contracts 缺少该导出会导致网站构建失败。
`packages/contracts` 源码目录不是网站运行时解析目标；实际消费的是
`node_modules/@vizly/contracts`，必须核对安装内容与验收归档一致。

## 文档行为

文档 `schemaVersion` 仍为 `1`，合法文档无需迁移。严格解析拒绝不存在的父节点、
自引用和循环，分别返回 `missing-node-parent`、`self-node-parent` 和
`cyclic-node-parent`，并给出具体字段路径。节点可以按任意顺序存储。
网站画布的节点 ID 可包含中文（例如自动生成的领域分组）。恢复适配器仅在内部
投影为便携 ID 来复用校验，保留画布原始 ID 和报告中的原父关系；不将公开文档
格式的 ASCII ID 限制强加给既有网站数据。

公开 SDK 调用者通过
`importLegacyVizlyDocument(input, { hierarchy: 'detach-invalid-parents' })`
显式准备历史文档恢复，并向用户展示返回的 `repairs`。不得在普通加载失败时
静默采用修复结果。节点、有效边和存储坐标保留；无法推断的绝对位置不作恢复保证。
重复恢复已经修复的文档不再产生修复项。其他结构错误仍然失败。

网站初始加载会检查当前画布及多页元数据中的每一页。发现异常后暂停初始化和
自动保存，提供异常关系列表、原始数据下载、取消和“备份并恢复”。恢复前先将
原数据写入浏览器独立备份键 `vizly-hierarchy-recovery-v1:`，并读回验证；
备份失败不继续。备份包含自动保存的原始序列化文本。用户清除网站存储时，
本地备份也会消失，因此需要长期保留时应下载原始数据。

取消不改原文档。审核期间数据改变时须重新确认；旧文档的确认不能作用于新文档。
只读加载不刷新或删除待审核源数据，当前打开的存储键不参与过期清理。

删除容器、取消分组或剪切容器时，存活子节点提升到最近存活祖先或根画布，
调整局部坐标以保持画布位置；移除被删节点关联边，保留存活节点之间的边。
相关锁定节点或锁定边阻止操作。撤销和重做恢复完整图。
旧式 React Flow 脑图节点通过工具栏删除时，将存活子节点重接到最近存活的
主题祖先；同批删除多个连续祖先时不连接到已经删除的节点。关系线移除，不转成树边。
该入口使用当前编辑权限与所属实例，角色降为只读后拒绝删除；恢复编辑权限后可继续操作。

新版 MindElixir 脑图使用独立的树结构。工具栏删除分支会明确提示后代数量，
确认后删除整支，保留其他分支；取消不修改内容。旧节点重接和新版整支删除已分别
验证撤销、重做、自动保存与刷新恢复，不能互相替代。此项验收不扩展真实多人协作
或同文档多视图的支持范围。

## 升级与回退验收

1. 同时固定 Core 和 contracts 的 tarball、SHA256、锁文件以及对应源码。
2. 验证安装文件逐项匹配，运行 Core 包门禁和网站类型、构建、Lint、单测及浏览器回归。
3. 对异常历史样本验证取消、备份失败、显式恢复、保存和刷新；同时验证合法样本不触发恢复。
4. 回退时使用上一组已验收的依赖和前端产物，不混搭新旧包、不删除本地备份。
   恢复结果仍为 schemaVersion 1，但实际旧版本保存／重开／协作回退测试仍须单独完成。

本地测试不替代真实账号与服务验收、正式 CI、部署验证或回退演练。
本次未交付新的 `@vizly/react` 包，不将其历史版本视为这组新包的配套验收结果。
