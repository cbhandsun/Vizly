# 布局空间优化：约束、行业方法与验证

日期：2026-09-06。范围：域级 Dagre 布局、泳道横向坐标分配、域／子域内 grid 和流式排布。

## 已确认的产品边界

- **泳道模式**：严格保持泳道边界对齐、统一流程方向上的长度、域顺序和归属；空间优化在这些约束内进行。
- **非泳道模式**：域按内容组织，可以采用更自由的分组、分块填空和紧凑排列。
- **子域内部**：不强制单行或单列；可采用 grid、流式换行、分层或独立分量组合。节点有先后依赖时，不能为了填满矩形把依赖关系打散。
- 不能缩小文字、节点内容或既定连线安全距离来制造空间收益。
- 普通可识别的桥接交叉仍按 `edge-routing-goals.md` 处理；节点穿越、端口失配和其他硬错误仍不能提交。
- 同时评估整图宽高、面积、可读比例、连线路径和稳定性；局部容器面积最小不等于整图最优。

## 行业方案与采用方式

| 方法 | 适合解决的问题 | 本次采用方式 |
| --- | --- | --- |
| 分离层级分配、层内顺序、坐标分配 | 层级更新后仍沿用旧坐标产生空白 | 泳道在全局排名之后重算横向分离约束；不改变流程排名 |
| 约束下的压缩、分组压缩 | 旧局部布局的列宽被扩展到整个泳道 | 同一流程带内保留顺序与通道，不同流程带复用列空间 |
| 独立连通分量装箱 | 短流程和孤立节点占据与长流程一样高的空白列 | 依据全图连接关系判断独立性，把分量在当前内容块内的几何作为整体，尝试横向和纵向填空 |
| 实际尺寸与目标宽高比 | 按节点数量开平方不能适配宽卡片和长卡片 | grid／流式排布比较实测宽高与间距后的候选列数 |

资料依据：

- [yFiles Hierarchical Layout](https://docs.yworks.com/yfiles-html/dguide/hierarchical_layout/) 区分 layering、sequencing 和 coordinate assignment，并提供 node compaction、分组和约束能力。这支持把“流程层级正确”与“坐标紧凑”分开建模。
- [yFiles Compact Groups 示例](https://live.yworks.com/demos/layout-features/hierarchical-compact-groups/) 展示组压缩；可变大小的普通分组与严格等长泳道需要不同约束。
- [ELK 后处理压缩](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-compaction-postCompaction-strategy.html) 提供多种压缩策略，默认关闭。说明空间压缩是独立优化阶段，并非统一降低 spacing。
- [ELK 独立分量压缩](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-compaction-connectedComponents.html) 专门压缩 disconnected subgraphs。
- [ELK Aspect Ratio](https://eclipse.dev/elk/reference/options/org-eclipse-elk-aspectRatio.html) 将宽高比作为布局选项。本项目 grid 候选采用 1.6 的软偏好，是产品选择，不是行业统一标准，也不是强制容器比例。

## 代码变化

### 泳道：按最终流程带重新分配列宽

原先先计算域内 Dagre，再给节点分配全局流程位置，但保留域内旧横坐标。原本同时占用多个列的节点，可能已经处在完全不同的流程阶段；这些历史列宽仍被算入整个域的宽度。

`domainDagreLaneCrossCompaction.ts` 将同一子域／自由节点桶内的节点建立有向分离约束。流程方向距离小于既定 48px 安全距离时，保留节点次序和间隔；不相互占用流程带的节点可共用横向空间。对左压紧、右压紧两组可行解取平均，让无额外约束的链保持居中。

压缩发生在边路由之前，不改节点大小、流程排名、泳道归属、外层统一长度或端口约束。最多处理每桶 256 个节点；非法几何、重叠起始带或没有收益时保持原坐标，由原有验证路径处理。

### 非泳道：整体移动独立分量

`domainDagreComponentPacking.ts` 保留按全图连接关系划分的独立分量在当前内容块内的完整几何，只平移分量。与域外节点相连的内容不会被当作局部孤立卡片。候选尝试按行、按列装箱；未提供父级预算时，宽和高都不得扩大；具有明确父级预算时，可在同排内容已有高度内比较局部形状。最终仍需通过整图布局与路由验收。

这个默认限制来自实际对照：初版只比较局部面积时，需求分配 TB 整图面积反而增长约 18.6%。该版本未保留；父级预算分支也不能仅凭局部面积更小便接受候选。

本次是有界矩形填空，不宣称求得全局最优装箱。并非把所有子域自动替换成 grid；有依赖的分层仍由 Dagre 负责。

### grid／流式排布：按实测尺寸选择列数

`domainDagreChildArrangement.ts` 比较候选列数的实际行高、列宽和既定间距，选择更适合阅读的内容矩形。显式水平、垂直排列保持其原意；grid 保持统一单元格，流式保持实测单元格。

例如 6 个 240×60 节点、40／30 间距，自动选 2 列；6 个 60×240 节点则选 6 列。使用同样的节点和字号，不靠缩放减少面积。此选列目标改善可读比例，**不保证每个 grid 候选的绝对面积都下降**。

## 二次复核：修复前的问题记录

日期：2026-09-06。本节保留修复前的复现与判断；后续实现见“统一修复”。前面的通过记录只覆盖当时执行的用例，不能证明所有排布组合都正确。

### 1. 优先修正排布语义在各阶段之间丢失

两项已通过完整 `DomainDagreLayoutStrategy.calculateLayout` 复现：

- **P1，泳道 flow 产生节点重叠。** 一个域／子域内放 6 个独立卡片，grid 输出两列三行、无重叠；flow 初排后被全局分层改成两列一行，最终产生 6 对重叠。`DomainDagreLayoutStrategy.ts:488` 把 flow 与 dagre 一起送入语义排名，`domainDagreSemanticLaneFlow.ts:129` 重写流程坐标，却保留流式布局重复的列坐标。
- **P2，域直属节点忽略排布选择。** 同一输入去掉子域，grid 和 vertical 都变成六列横排。`domainDagreNestedLayout.ts:144` 始终用 Dagre 放置域直属节点；只有第 89 行的子域路径使用 `nodeArrangement`。

应明确区分“自动流程分层”和“显式局部排布”：flow、grid 的内部行列关系必须成为后续阶段保留的约束；域直属叶节点和子域叶节点使用一致的排布入口。含子域和直属节点的混合域，可将直属节点组织为独立内容块，再参与域级布局。

修复还应检查 `reverseLayeredLayoutGeometry.ts:185` 对 flow 原生反向语义排名的假设。回归矩阵至少覆盖 TB／LR／BT／RL、独立节点／有边节点、有子域／无子域／混合域，并在完整策略最终输出检查节点无重叠、包含关系与用户选择是否生效。

此处只确认了布局策略输出；未操作用户浏览器，尚未确认重叠候选会被界面事务拒绝还是显示出来。不能据此断言它就是此前切换回退的根因。

### 2. 泳道严格对齐，不应等同于所有孤立节点挤在第一层

**P2，已量化的空间浪费。** 在语义泳道模块中，6 个 240×80 的链节点占 368×1032；增加 12 个孤立节点后变成 4688×1032。链的位置完全不变，12 个孤立节点却全部停在 `y=200`。这些节点没有流程阶段依赖，仍按第一层展开，宽度随数量线性增长。

建议保留连接流程的位置，把无阶段依赖的节点组织成独立内容区，按泳道已有高度分行填空。泳道边界对齐、等长、顺序和归属保持为硬约束；“孤立节点必须与流程起点同层”不应作为默认业务约束。现有相关测试需要区分这两类要求。

### 3. 最终坐标应统一求解，再确定容器大小

**P2，已确认阶段顺序造成漏优化。** `domainDagreSemanticLaneFlow.ts:121` 先压缩横向坐标，第 219 行才按 `index * flowGap` 错开同层分支。压缩器依据的流程占用关系随后发生变化。前文“全局排名之后压缩”不能理解为“所有后续位移已经结束”。

12 路并行分支、240×60 节点的模块复现，最终内容包围盒是 4200×1628；同一压缩器读取最终流程坐标后，可生成 240×1628 的候选。**这只证明旧约束漏掉了候选；收窄后的端口、连线和语义可读性尚未验证，不能把 94.3% 当成交付收益。**

应先确定流程阶段、局部排布与节点次序，再计算横向分离约束和容器范围。候选必须经过完整路由门禁；不能在求解后又由其他阶段任意覆盖节点坐标。

### 4. 从固定局部目标升级到父容器约束下的少量候选

**P3，优化能力缺口。** 分量装箱要求宽高都不增长（`domainDagreComponentPacking.ts:89`），grid／flow 则偏好固定 1.6 比例（`domainDagreChildArrangement.ts:34`）。二者都没有父容器可用宽高来协调局部形状。

12 个 240×60 独立节点的局部复现：Dagre 和当前装箱均为 4200×60；flow 为 600×560，局部面积反而增加 33.3%。哪种更好取决于父级排布和阅读场景，不能单凭局部面积或固定比例决定。前面已有放宽装箱条件导致整图面积增加 18.6% 的反例，应保留现有保护，直到整图评估可用。

建议每个内容块生成少量有界候选：有依赖的主体保持分层，独立卡片生成网格形状，符合条件的同级叶子可考虑 grid／bus 子组件。父层在泳道约束内比较整图宽高、可读缩放、连线长度／折点／回绕，以及未改动节点的位移。昂贵路由只验证筛选后的少量候选，避免增加切换超时。

### 5. 大图的“适应全图”需要独立的视图契约

**P2，已通过真实调用函数量化。** 工具栏 `useFlowchartHostActions.ts:18` 发出 fit，`DiagramControlBridge.tsx:129` 调用 `computeDiagramFitViewport`。后者在 `diagramControlFit.ts:1`、第 79 行起将最小缩放固定为 0.32。

用上轮企业图 9845×3304、1948×1037 视窗、默认桌面安全区计算，可用区域为 1796×873，但函数返回 32%，内容显示尺寸为 3150.4×1057.28，无法完整进入视窗。这会让用户仍感觉图很散、看不全，即使布局面积已经下降。

建议明确分开“全图概览”和“适合阅读”：概览按实际内容范围缩放，阅读模式保留可读缩放并支持定位子域。当前 fit 只读取节点范围，后续还应纳入实际连线路径和标签范围。不能通过继续压缩布局来补偿视图函数的缩放下限。

### 行业依据与建议顺序

- [yFiles Hierarchical Layout](https://docs.yworks.com/yfiles-html/dguide/hierarchical_layout/) 明确区分分层、排序、坐标分配；支持分组、自定义子组件与 grid components。Grid components 主要针对适合总线连接的根节点和邻接节点，并非任意有依赖子图都适合强制网格。
- [ELK Post Compaction Strategy](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-compaction-postCompaction-strategy.html) 将后处理压缩建模为独立阶段，支持在布局流程中明确其职责。
- [yFiles Incremental Layout](https://docs.yworks.com/yfiles-html/dguide/layout-incremental_layout/) 可参考原有坐标与增量标记安排新增内容。当前泳道保存的是排名模式选择，不等于完整的增量坐标布局；后者适合作为后续稳定性优化，暂未对用户编辑操作做量化验证。

建议顺序：**排布语义和无重叠 → 孤立内容分块及最终坐标求解 → 父容器候选评估 → 增量稳定性**。全图概览问题可以独立修复。以上是对当前架构的演进建议，无需先替换整个布局引擎。

复核证据：`tmp/layout-capability-full-probe.ts`、`tmp/layout-capability-free-domain-probe.ts`、`tmp/layout-capability-audit-probe.ts`、`tmp/layout-algorithm-audit.ts`。本轮仅运行这些定向复现与 fit 纯函数计算，未修改生产代码、未重新运行全仓门禁；这些临时探针不能替代修复后进入 CI 的回归测试。

## 统一修复

将布局分成明确的阶段：局部内容排布 → 流程排名 → 最终坐标分配 → 容器定界 → 布局及路由联合验收。后续阶段必须保留前序阶段的排布语义；空间优化只能产生候选，不能绕过最终验收。

重复布局首先统一到绝对工作坐标，结束时再恢复父子相对坐标，旧运行时坐标缓存不参与最终覆盖。子域生成保持幂等并处理 ID 冲突；重复 ID、缺失或非法父级、循环及超深层级在清理旧父级字段前拒绝。

- 显式 flow／grid 不再被语义泳道排名覆盖。域直属节点与子域内容使用一致入口；混合域以内部内容块参与域级布局，内部辅助块不会进入业务模型。有依赖的连通块保留流程层级。
- 泳道在最终流程位移完成后分配横向空间；孤立卡片利用统一泳道已有高度形成独立内容区，不改变连接流程的排名。
- 普通域只在同排子域已有高度预算内比较局部形状。未获得父级预算时，继续要求独立分量装箱的宽和高都不增加；不恢复曾导致整图面积增加的“只看局部面积”规则。
- `layoutGeometryConstraints.ts` 提供与布局算法分离的几何报告，检查有限尺寸、有效父子关系、节点分离、真实容器包含和泳道对齐。`layoutCandidateAcceptance.ts` 将几何及约束摘要与既有路由摘要绑定；Worker 的路径收据保持原有职责。
- 显式布局，包括无边图，在提交前重新核验同一候选。语义泳道优先采用明确域顺序；未指定时保留稳定的域声明顺序，内部节点的流程排名不再重排域。
