用户已明确授权按收益与总成本混用 Astra、Terra、Luna，并匹配思考深度。局部且契约明确的实现默认 Terra medium；机械核对优先主 agent 直接完成，确有独立并行收益时才用 Luna low/medium；未解决的跨阶段算法或并发不变量才用 Astra high。不能只因问题严重就升级，也不为用便宜模型而重复返工。不承诺未测量的价格或节省比例，不重复继承整段上下文。

不默认使用 max/ultra。不按文件行数、问题严重程度或“今天剩余额度多”机械定深度；例如 P1 可以是简单条件遗漏，局部功能也可能隐藏复杂状态机。

升级触发：出现未预见的跨模块所有权/协议变化，或两个不同且可区分的实验仍不能定位问题。子 agent 返回“已确认事实、已排除假设、剩余矛盾、下一实验”，主 agent 重新判断是否需要升级。工具错误、环境没启动、测试命令写错不触发思考深度升级。

降级触发：高深度任务已产出明确契约和可复现根因，剩下是机械实现、补固定边界或整理结果。将后续独立任务以 medium/low 启动，不让 high agent 继续承担日志整理。

这些是检查点，不是尝试次数耗尽就停止交付；遇到新证据应继续推进。不能用预算理由减少必需验收或把未修复问题标完成。

**四、实际调度方式**

当前协作工具支持在 spawn_agent 时指定 reasoning_effort。本轮已经用 fork_turns=none、reasoning_effort=low 启动只读入口核对子任务并收齐结果；无需为此新建用户侧任务或安装调度框架。

实现阶段使用如下真实参数形状，由主 agent 填入当前任务卡、文件所有权与验收证据：

```json
{
  "task_name": "r1_route_failure",
  "fork_turns": "none",
  "reasoning_effort": "high",
  "message": "执行 R1a/R1b 的已就绪子任务。先读项目 AGENTS.md 和本计划的指定任务卡；仅访问给定边界；保留已有修改。输入为最小夹具、同一 requestId 的最终响应与截图。明确复现和验收，修改范围由任务卡约束；不要启动子 agent。返回根因、改动文件、检查结果、未解决风险和证据路径。"
}
```

任务未就绪不启动实现 agent：依赖、输入、写入范围、验收、允许的副作用必须齐全。读图/浏览器必须指定独立会话和唯一使用者，避免同时操作同一页面；同一工作区的生产 build、预编译生成和完整 verify 只由一个 owner 执行。

默认并发是主 agent + 1 个执行 agent。确有独立工作时，允许主 agent + 1 个写入 agent + 1 个只读验证/诊断 agent；通常保留第 4 个槽位。只有文件、状态和运行资源都不冲突，且并行能减少关键路径等待时，才考虑第二个写入任务。

不要为五个迭代同时启动五个 agent；不要让多个 agent 解同一问题后互相比答案。R1/S1 这类高风险变更在冻结候选后安排一次独立差异审查，审查只看不变量、差异和证据，不重做整个项目评估。

同职责、同深度的后续工作可以复用已存在 agent。当前 followup_task 不能指定新的思考深度；要升级/降级时，先让旧 owner 停止写入并产出交接摘要，再启动新 agent，不能只在提示词里说“切到 high”就声称配置已更改。

**五、Token 使用规则**

1. 默认不复制整段审计历史。任务输入用短任务卡 + 相关文件/夹具路径 + 一条失败断言；fork_turns=none 时必须显式带上项目路径、适用指令和已接受的约束，不能因节约上下文丢规则。
2. 首轮只读责任范围内模块。若需要扩大搜索，说明现有证据为什么不足；禁止每个 agent 重读 1900 行历史会话计划。
3. 原始日志和截图留文件。回传一般控制在 600–1000 中文字，只列关键差异、通过/失败与证据路径；复杂根因写单独文件供需要时读取。
4. 提示中的简短输出只是回传目标，不是隐藏推理 token 上限。当前 spawn 工具没有 per-agent token_budget/max_tokens 参数，不能声称已设置硬额度。
5. 不虚构每个 agent 的实际 token 数。工具提供 usage 时据实记录；不可用时标记未知，记录深度、启动次数、返工次数、重复检查与产物，作为调整依据。墙钟耗时不换算成 token。
6. 没有新证据时不重复请求同一份分析。一次失败先分类：实现失败交回 owner；环境问题修环境；新增需求另开任务卡；复杂推理才升级。
7. 不为微小改动必设独立 reviewer。确定性低风险任务由主 agent 复核；路由会话、最终几何授权和跨域语义保留独立高深度审查。
8. 同一个高成本问题至多保留一个活动分析者。xhigh 也只拿最小反例和剩余矛盾，不重新加载全部项目上下文。

OpenAI 官方说明，子 agent 各自运行模型与工具会增加总 token；medium 是平衡起点，复杂逻辑可用 high，更高 effort 会增加时间和 token。因此本计划控制“是否需要 agent”与上下文范围，再调深度，而不是只追求低档位。[官方 Subagents 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)

**六、验证分层与复用**

子任务迭代：先让对应 bug 回归失败，再做最小修复并运行该文件/相关 shard。可复用 npm run test:run -- <明确测试文件>；正确保留 Node/jsdom 环境声明。不要为凑绿色结果使用 passWithNoTests；现有 test:changed 的空测试成功也不能代替新增回归已执行的证据。

| 范围 | 可复用入口；由 owner 选择相关范围 |
| --- | --- |
| 会话/最终路径 | npm run test:ci:core-components-shared-flow；npm run test:ci:core-components-shared-flow-routing-quality |
| 组件/标签/布局 hooks | npm run test:ci:core-components-c；文本测量另有 npm run test:ci:dom-utils-layout-dom |
| 浏览器协议与检查工具 | npm run test:ci:core-components-shared-browser-contracts；实际页面用 npm run verify:display-routing-browser |
| 泳道算法 | npm run test:ci:routing-layout-strategies；相关 utils 用 npm run test:ci:routing-layout-utils |
| 路由改动的影响范围 | npm run test:changed:routing；结果需核对是否实际包含新增回归 |
| 新增/移动测试 | npm run check:test-ci-coverage |

以上是入口映射，不表示这些入口已经覆盖本报告所有新缺陷。例如浏览器契约测试不能代替实际 SVG 检查；新增审计器测试仍须进入 runner 调度。新增 shard 才修改 scripts/lib/test-ci-shards.mjs，优先复用合适的现有环境。

每个交付批次由主 agent 冻结当前候选，统一执行：

```text
npm run verify
npm run typecheck:ts6
npm run verify:display-routing-browser
```

当前 verify 已包含静态安全、架构、类型、Lint、生产 build、bundle 和完整 test:ci，因此不让每个子 agent 再各跑完整 verify。它不含 typecheck:ts6 或专项浏览器入口，二者不能漏。实际浏览器入口的参数、构建与启动前提以实施时脚本为准；不得假设一个不存在的 --case 参数能缩小验收。

开发过程可只测当前反例；批次交付仍完成对应风险的代表图矩阵。若既有专项入口本来执行更完整的矩阵，不为节约时间删场景或修改默认范围。涉及移动路由行为时补 verify:full/既有移动验证。最终 I5 跑完整的四类代表图、四方向、跨引擎序列与合成用例。

结果缓存绑定实际源码/构建身份、命令、运行时、输入夹具和退出码。只有证据对应同一未变候选、影响范围未扩大时才能复用；一旦相关源码变化，重跑受影响检查。不能把 HEAD 相同当作 dirty worktree 相同。

路由源码影响预编译身份时，按现有生成→构建→独立复现流程处理。相近修改在一个职责清楚的批次收口，避免每个小改动都重建所有产物；禁止手工改 hash/manifest 伪造同步。Windows 下保留现有 worker 配置，避免多个 agent 同时启动重型 Vitest/build/browser 争抢内存。

依赖原则上不变；确需新增直接依赖时单列任务并用项目规定的 npm 12 做 npm ci。不能用本机旧 npm 完成依赖升级后声称已验证可复现。

**七、每批共同验收矩阵**

- 基础：空图、单节点无边、孤立节点、并行与汇合、跨泳道反馈、嵌套子域、严重不均衡分布；边界输入与失败路径进入统一 CI。
- 图形：四代表图、TB/LR/BT/RL、泳道/非泳道切换；最终渲染路径端点正确，避障、净距、主干语义不退化；模型 source/target 不变。
- 交互：连续意图和过期结果、拖拽后拒绝、折叠/展开、布局失败；选中项、busy、提示与画布一致。
- 标签：普通/长中文/密集短条件、当前实际路径、标签互避和箭头净距，50/100/150% 与既有低缩放 LOD；保留手工标签偏移的显式语义。
- 持久化：保存重载、页面切换、三页新增/复制；除已有布局坐标对照，还补手动标签位置与文本修改的页面隔离。
- 泳道：同组流向轴等长；明确区分必要流程长度、算法冗余和需分段视图解决的空白。不用单独裁切、全体零间距或改变业务边方向换取紧凑。

**八、交付记录与启动约定**

每批返回一份简短记录：任务 ID、实际深度/升级原因、根因、改动文件、执行的检查、原始证据路径、尚未解决风险、下一批依赖。所有预算数据必须标明实际/估计/不可得。

规划时仅新增本计划；当前实施状态以文首检查点为准。实施依 P0→G1/R1a→R1b/U1 的顺序派发；已有 agent 授权足以按任务复杂度调度，不为每个 agent 重复询问。普通实现决策由主 agent 自主完成；涉及互不兼容的用户可见泳道契约时，先做两份可比较的例图与约束对照，再集中请求一次选择，避免抽象问题反复打断。

大范围架构修改使用独立 codex/ 分支。创建隔离工作区时必须保留/明确带入当前有效修改，不能悄悄只从 HEAD 开始而漏掉评估基线。只暂存本批文件，不默认 git add -A；提交、推送和发布按当时用户授权执行。
