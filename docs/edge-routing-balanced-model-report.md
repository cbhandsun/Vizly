日期：2026-09-05（本机时区）。分支 `codex/layout-routing-iterations`，路由版本 `17`。

2026-09-06 续修：普通入口的端口、通道初始化和布局切换修复已整理到 [普通入口修复记录](edge-routing-normal-entry-fix.md)，当前路由版本为 18。本文件保留上一轮限定场景的历史证据。

## 结论与边界

**后续普通入口复验已重新打开此问题。** 用户报告“标准流程 → 泳道布局”回退，以及恢复页面时端口错误、穿节点。下述通过记录使用了 `precompiledCapture` / `precompiledRegenerate` 的全质量采集入口，带有既有路径种子且绕过自动保存数据；它不能证明普通页面的 12 秒交互 Worker 入口通过。普通恢复数据实际没有 computedPath 和大部分自动 handle，出现 `worker-timeout`；真实泳道切换约 9 秒后因净距门禁拒绝。以下生产记录保留为限定场景的历史证据，不能作为当前问题已经解决的结论。

原企业架构图的运行时拒绝问题已经有当前生产构建的端到端通过证据。此次主要改变是约束模型：把可读交叉作为有限成本，把节点碰撞、端口错误、异常重叠及无法表达清楚的主干接点作为必须解决的问题。合法主干按多边事务维护。

这不等于任意图都能在固定节点和端口下找到解，也不证明路线全局最短。`hardClean` 仍不能替代视觉、交互、缩放和导出四层验收。以下结论只覆盖列明的构建与样例。

## 根因与修复

| 根因 | 当前处理 |
| --- | --- |
| 把普通交叉当成不可接受的硬错误，有限搜索不断产生外绕和局部反弹 | 统一普通交叉、歧义交叉及共享主干分类；普通交叉与长度、弯折共同计价，相邻边交叉成本更高 |
| 多条边共同拥有主干，却逐边修复净距 | 以整组主干为事务单位，支持安全同伴通道、端口内平移；只对有实际问题的合格组使用有限搜索预算 |
| 原始路径可跳线，但双主干分叉与汇聚重合，绘制分段后丢失跳线 | 为分叉和汇聚预留独立中间通道；需要移动汇入通道时同时移动其共享成员，保留两端身份与固定端口 |
| 完整缓存路线和增量补丁使用同一种递归合并规则，已清除字段被旧数据恢复 | 完整预编译路线替换路由字段；可信增量补丁明确表达路由字段删除，保留业务数据 |
| 几何、主干审计、实际 SVG 对精度和交叉的判断不一致 | 统一交叉规则；修正镜像通道顺序、取整后共线锚点识别；实际 SVG 必须覆盖每个交点，元数据标记不算证据 |
| 仅剩净距问题仍重复整套最终修复 | 在整图稳定化重试前使用已有的净距事务；WMS 回归保持一次最终评价上下文访问，原计数断言不变 |

没有新增按企业图、节点或边 ID 分支的生产规则，没有提高搜索和耗时上限，也没有修改 baseline 文件。历史双主干几何被保留为固定回归输入，新生成路线继续独立检查全图质量。

测试口径随目标模型同步迁移，并非所有旧断言原样保留。需求分配图的 e3 旧有单边绕行比 `≤1.1` 与当前有限交叉成本冲突：当前比值约 `1.117`；存在少走 178px 的可行四弯候选，但全图交叉成本由 9 增至 22，总可读性成本从 11,425.005 增至 11,437.115。回归改为枚举节点净距边界上的单调通道，确认存在更短的合法路线、但它们的全图成本更高；原有全图硬约束、实际桥接、弯折、总绕行上限与 15 秒预算继续验证。e13 的旧比值与 48px 净距及固定锚点不相容，改为验证选定绕障通道的最短长度。以上不构成全局最优证明。
