- 验证工具已有启动探针；普通用户已有挂载前恢复、入口资源恢复和 Worker 安全摘要，但还没有完整跨阶段轨迹；历史偶发空白根因未明。
- 拓扑浏览器矩阵已接入稳定性指标，覆盖增删、尺寸调整、多节点/子树移动、端口策略、折叠/展开；缺口是最终连线影响组、更多业务图和连续操作。
- 新指标只比较编辑前后两次状态，且路径长度/拐点只统计非关联保留边；不能证明中间无跳动或关联边无绕远。
- 无关节点位置和孤立编辑连线保持已有门禁；其余连线变化代价阈值尚未完整建立。性能流水线成功不等于所有稳定性退化都已被拦截。
- 有界局部联合决策不等于全图全局最优。单个修复器的规模限制不等于应用的整体支持上限。
- Bundle 最近本地构建为 9970.43 KiB，硬上限 10000 KiB，余量仅 29.57 KiB；启动 JS 为 520.34 KiB。`LayoutOptimizer` 混合静态/动态导入仍需核查和处理。

## 4. 各批次执行契约

### I0：恢复当前完整验证

先读取失败测试及对应状态、持久化、卸载监听逻辑；在相同运行时运行单用例与所属分片，区分单测可复现和仅分片可复现。
检查保存完成的等待边界、验证状态是否失效、监听器清理和测试间状态污染，不预设其中任何一项就是根因。
必要时用有界重复实验检验明确假设，并记录失败次数；禁止无限重跑、增加任意等待或放宽断言。
若触及配置、持久化或日志，补敏感信息和失败路径测试。恢复相关分片后执行风险匹配的完整验证并确认覆盖率作业运行。
生产修复与测试编排修复按真实职责拆分；不能只因失败文件未在上一批修改就视为无关债务。

### I1：统一启动诊断，保存失败现场

建议拆成两个可独立提交的实现批次，线上诊断作为单独决策点：

1. 统一 `display-routing-browser-wait` 与冷启动生成入口的阶段、错误分类和预算；补 `final-quality-rejected` 等实际终态。
   对求值失败、求值超时、页面错误、Worker 错误和质量拒绝使用不同安全代码。
   审查冷启动脚本现有原始 message/reason：截断不能代替脱敏。
2. 每个样本完成立即保存有版本号的安全结构化摘要。后续样本失败时保留已完成数据和失败阶段，不依赖最终一次性汇总。
   诊断读取也必须有界；宿主保存已经获得的阶段摘要，避免渲染器失联后只能返回空证据。
3. 若要覆盖普通用户启动，独立设计轻量、本地、有界的诊断模块及用户可导出的安全摘要。
   默认不新增远程遥测，不保留原始内容，不把诊断业务堆入 composition root；引入生产探针前验证自身开销。

阶段至少区分页面资源、应用就绪、Worker 就绪、计算完成、事务提交和绘制稳定。
首次观测时间与独占阶段耗时分开命名；Worker 构造、首条进度消息或首条路径均不能充当最终就绪。
故障注入覆盖资源失败、初始化异常、Worker 创建/消息失败、计算超时/取消、质量拒绝、主线程失联以及诊断读取失败。
单元测试与真实浏览器验证分别选用正确环境，明确哪些故障只在测试中模拟。

退出条件：每类已定义失败有可核验分类和安全证据；原超时预算不增加；无内容/秘密泄露；完整日志缺失也不会导致等待器再次无限等待。
历史偶发启动问题只有在复现并建立因果证据后才能标为已修复。

### I2：复用现有操作矩阵，建立稳定性门禁

先扩展 `check-test-ci-coverage` 对 `scripts/lib/*.test.mjs` 的发现与 CI 调度覆盖校验，补漏收录、非法路径和已正确收录的测试。
不以测试文件名存在代替 runner 实际运行，也不批量新增重复 Vitest 进程。

将新稳定性采集接入现有节点增删、边增删、尺寸调整、多节点/子树移动、端口策略、折叠/展开矩阵。
先用物流稳定入口验证集成，再扩展 WMS、需求分配、TMS 的代表编辑；不立即穷举全部组合。
对折叠隐藏对象、父容器后代、删边和改接分别定义可见/可路由集合及比较口径，避免把预期变化误报为退化。

指标分层：显式编辑对象、允许联动的受影响集合、组外保留对象、全图。
保留节点位移、端口变化、路径变化、长度、拐点、增删/改接计数；报告分母，区分不可用、零值和无适用对象。
增加路径规范化比较：区分共线分段变化与真实几何变化，保留原始点序列指标以便诊断。

阈值基于场景契约及原有约束制定。预期无影响场景可断言保持；有意联动场景需定义范围和代价，不机械要求所有变化为零。
只观察到历史最大值，不足以证明该值就是合理阈值；实验阈值与发布门禁分别标记。
退出条件：新增操作数据完整、已知退化反例能使门禁失败、正常必要变化不会误报，测试全部进入统一 CI。

### I3：测量编辑过程与阅读质量

按用户操作序列验证连续拖动、拖动后立即撤销/重做、编辑与布局切换交错、保存重载以及标签手动调整。
遵守产品现有 busy 禁用契约；强行激活隐藏入口的测试不能冒充真实用户路径。

在终态比较之外记录有界时间序列：组外节点最大位移、端口/路径切换次数、标签位移与遮挡、从释放到连续安静窗口的耗时。
定义采样频率、事件上限、采样开销和丢样状态；采样遗漏不能当作过程稳定。
分别测量关联边、受影响组和全图的路径长度与拐点，防止组外稳定掩盖关联边绕远。
验证过期/取消响应不覆盖当前状态；撤销重做恢复正确业务状态；展示避让不改写保存的用户偏移。
覆盖长标签、密集标签、缩放往返和必要导出路径，报告挂载、可见、遮挡与语义归属的不同口径。

退出条件：已知“中途跳动后恢复”的反例可被检测，真实操作有确定终态和清晰失败证据，过程与最终 DOM/持久化一致。

### I4：复杂图语料与联合优化

先盘点具体修复器的候选、节点、边和深度上限，测试边界前后及回退行为。
例如 perimeter 修复器的 48 边/128 节点限制只代表该策略范围，不是产品图规模上限；不得直接提高常量作为解决方案。

语料包含四代表业务图、待确认的企业复杂图反例，以及按节点规模、边密度、嵌套、反馈环、固定端口、连通分量和分布不均衡划分的确定性合成图。
图 ID 只用于夹具标识，生产逻辑不得特判。先建立小型组合覆盖，发现问题后补针对性的组合，不用全排列消耗验证预算。
历史失败必须在当前版本复现后才作为当前算法缺陷；保留原失败证据及构建身份。

每次研究：固定输入与约束 → 提取最小反例 → 比较有限方案 → 小型回归 → 真实 Worker → 生产浏览器 → 同条件质量/性能对照。
候选方案可以探索局部节点调整与端口/通道共同选择，或布局候选增加路由代价反馈；具体选择由反例决定。
优先满足包含、分离、泳道归属、端点、避障、非法重叠、固定端口等硬约束，再比较面积、流程方向、长度、拐点、普通交叉和稳定性。
普通可读交叉与非法重叠分开统计，不一概追求零交叉。

退出条件：收益来自提交中的算法变化，在相同构建条件与采样口径下成立；无硬约束和代表场景退化；计算/候选预算有界；无全局最优承诺。
若收益不稳定或只改善局部指标却明显恶化全图，停止该方案并保留实验结论，不继续叠加补丁。

### I5：加载、性能和维护成本

先分析真实静态导入与资源下载链，再决定拆分 `LayoutOptimizer` 等职责；动态 import 语法存在不代表实际懒加载。
测量总 JS、启动 JS、gzip、实际下载资源和懒加载功能首次打开成本，不只看单个 chunk 变小。
分别记录计算、Worker 启动与传输、解析应用、实际绘制、长任务和内存；采用相同输入、机器条件及明确冷热状态对照。
初筛用少量样本，最终性能验收沿用当前发布采样要求；三样本 p95 不代替长期尾延迟结论。
大型性能实验独占本机，避免与 build/test 并发产生资源竞争。
依赖升级不混入算法修复；必要升级按风险分批，使用 npm 12 的 `npm ci` 验证并提交 lockfile。

退出条件：原 bundle 与路由预算通过，实际余量或关键路径成本改善有证据；新增维护复杂度与收益相称。

### I6：最终验收与交接

使用同一目标提交执行代表图、方向与必要跨引擎序列、保存恢复、多页隔离、增量编辑、标签与视图、导出的风险匹配矩阵。
汇总每个场景的状态、指标、构建身份、证据位置与未覆盖边界，不将重合场景相加夸大覆盖量。
完成必需类型、架构、安全、Lint、统一测试、生产构建及 bundle 门禁；按范围运行 `verify:full`，记录未执行部分及理由。
远端必须包含目标提交，必需 CI 实际完成，覆盖率不能跳过；后续本地分支与远端差异需明确。
本批交接必须列出未完成项、阻塞、已验证范围、影响与下一步。

## 5. 动态代理：优化总成本，不为并发而并发

默认主代理直接推进，不强制建立“侦察→实现→审查”三代理流水线。
主代理负责拆解、验收契约、差异审查、冲突裁决和最终提交；也直接完成已经掌握上下文的明确修复。
先考虑一次检索、批量工具调用或确定性脚本是否足够，再考虑子代理。

派发前记录四个信号，采用 0/1/2 的定性等级，不机械相加：

| 信号 | 低 → 高 | 如何影响调度 |
| --- | --- | --- |
| 范围 | 单模块 → 多模块 → 跨代码、配置、CI 或四个以上模块 | 决定文件边界及需要共享的上下文 |
| 不确定性 | 已复现已定位 → 多个待验证假设 → 需要跨日志、代码、外部行为推断 | 决定推理能力，不等同于需要更多代理 |
| 返工风险 | 文档/固定调整 → 常规实现 → 安全、持久化、状态事务、核心门禁 | 决定独立审查和验证要求 |
| 等待占比 | 主要在推理 → 混合 → 主要为构建/测试/CI | 等待高时减少活跃推理，不触发模型升级 |

| 模型与深度 | 适合的任务 | 使用边界 |
| --- | --- | --- |
| Luna / low | 可独立交接的文件索引、状态整理、固定配置核对 | 简单工具调用主代理能直接完成时不派发 |
| Terra / medium | 已有边界的模块实现、回归修复、常规失败定位 | 默认实现选择，不重复做已完成调查 |
| Sol / high | 跨模块安全边界、状态竞态、复杂图诊断与架构取舍 | 有证据时直接采用，不先让低配模型反复试错 |

这些模型档位来自项目约定，不是外部研究证明的性价比排名。按真实返工与交付结果调整。
沿用当前负责人通常可减少交接成本；若上下文已过多且无关，则使用清晰证据包重启有限任务，不无限复用旧会话。
升级必须说明新证据和待裁决问题；同一假设被证伪后更新诊断，不用更换代理重复同一试验。

只有满足以下条件才并发：子任务有独立输入与产出、无未决接口依赖、文件所有权清楚、主代理有同期可推进工作、预计收益超过交接审查成本。
默认至多一个子代理；确有两个独立瓶颈时才增加第二个。共享主工作区保持一个代码写入者；只读调查/限定审查可并行，但不同时运行重型验证。
实现者完成交接前不得让另一代理并发修改相邻模块；主代理避免重复实现，验收仍需检查关键原始证据。
安全及核心事务允许一次针对性独立审查，这是有目的的质量成本，不属于无效重复。

每次启动显示：任务、模型、深度、文件范围、已有证据、预计产出、验收条件，以及它能减少哪个阻塞。
每次完成显示：实际产出、验证结果、减少的阻塞、未解决项、是否返工及原因。
无法说清派发收益时不派发。模型等待工具或 CI 时不创建无关子任务维持并发。

## 6. 上下文与证据管理

每批维护一个简短证据索引，包含：目标、验收条件、提交/文件版本、已证实事实、已排除假设、失败用例、产物位置和待办。
代理仅接收该任务必要上下文和相关项目规则，不默认复制完整对话、整个仓库或历史流水线日志。
大型日志和报告保存为文件，返回安全摘要与路径；只读取与当前假设相关片段。原始产物不进入代码提交。
结论必须绑定提交或文件版本；文件变化后重新判断哪些证据失效，避免复用陈旧结论。
必要的安全核验、差异审查和不足证据补读不能为了省 token 跳过。
没有实际用量数据时不声称节省了多少 token 或费用；模型档位、代理数或工具次数仅是辅助记录。

## 7. 验证、资源与发布控制

- 前置核对实际 Node/npm 可执行路径和版本（Node 22.22.2+ 且小于 23，npm 12）、Windows 路径/URL、进程退出、浏览器二进制、端口及构建身份。

- 架构变化运行 `check:architecture`；边界/日志/持久化变化补安全测试及 `check:secrets`；DOM sink 变化运行相应检查；新增测试必须实际进入 `test:ci`。
- 跨模块、生产算法、架构或依赖变化优先完整 `verify`；TS6 兼容门禁保留。相关变化运行生产构建和 bundle 检查。
- 文档规划变更不重复全量测试、构建和 30 次性能采样；实施阶段不能借此跳过其必需验证。
- 同一批次合理复用未变化代码的验证结果，但最终发布证据必须明确目标提交与实际执行范围。
- 构建、全量测试和性能采样串行，性能采样优先独占。CI 重跑前先定位失败作业及步骤。
- 优先使用状态变更事件或阻塞等待；没有事件能力时每约 1–2 分钟检查，长时间无变化再退避。单次工具等待遵守当前环境限制；不反复读取相同输出。
- 直接在当前主工作区工作，不建立新工作树。保留现有用户修改，按明确文件列表暂存，禁止 `git add -A` 和破坏性 Git 操作。
- 一个独立职责完成即本地提交；同一验收批次可包含多个小提交。批次验证完成再统一推送，减少微小修改导致的流水线重启。
- 当前 CI 红灯必须先闭环，再推送后续生产功能批次。文档提交与修复提交保持分离。
- 推送前检查远端是否前移、必需检查和适用保护规则；若使用 PR，提前检查未解决 review threads。只有规则允许时直接 main，不能绕过必需审批。

以“通过约定验收的一次交付”为单位，分别记录质量、时间和资源，不把不同单位生硬相加：

## 10. 行业依据与适用限制
