# 本地协同服务

独立 Node 服务，仅监听 `127.0.0.1`。它不是公共演示服务，也尚未成为生产部署。
不使用 service-role 权限；Auth 验证身份后，用该用户的令牌查询图表和协作者，保留 RLS。

1. `npm run collaboration:build`
2. 在已忽略的 `.env.collaboration.local` 配置 `SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`、
   `VIZLY_COLLABORATION_ORIGINS`（逗号分隔的完整应用 Origin）、可选端口和数据目录。
3. `npm run collaboration:start`
4. 本地应用使用 `VITE_YJS_WEBSOCKET_URL=ws://127.0.0.1:5420`，重新构建后生效。

访问 `/health` 可检查就绪；日志只写固定事件，不写 URL、查询参数、凭证或图表内容。
房间必须为 `vizly-room-<云端图表UUID>`。本地模板ID和任意字符串房间会被拒绝。
客户端要求 URL 房间与当前图表 ID 完整匹配，拒绝其他图表的房间、非法字符及截断碰撞。
设计器完成初始化前，客户端保留最新远端快照并重试提交，不发布尚未就绪的本地画布。
待提交重试在换房间或卸载时取消；带删除历史的空远端文档也会被提交，避免恢复旧节点。
客户端在线状态只发布本身份的更新；连续光标移动合并至每秒最多5次，最终坐标会补发，
离开状态立即发送。服务仅接收有界有限坐标，成员身份由服务覆盖，其他字段丢弃。
鉴权较慢时，服务对每个连接尚未处理的在线状态保留最新一份，避免临时状态积压；
图表修改通过Yjs增量合并保留全部操作，不用新快照替换旧快照。客户端最多每200ms
发送一次普通文档增量；握手不延迟，关闭时发送最后一批。服务对每个连接待处理的
普通增量做有预算的CRDT合并，完整候选校验、权限验证和持久化成功后再广播。
角色检查和资源限额不变。已有120ms替代鉴权延迟下的600帧文档/光标并发回归，
不代表真实云端双账号或生产压力验收。
自定义协议消息4告知已验证的 `editor:fields-v1` 或 `viewer:fields-v1`。客户端在完成首次同步且收到编辑权限前
不发布本地画布；浏览器 BroadcastChannel 被关闭，避免绕过服务权限转发更新。

服务在每次收发前校验权限，并每3秒检查已有连接。失效身份或撤权会关闭连接；查看者
只允许不改变状态的同步回应。消息、完整文档、房间、连接、队列和频率均有限制。
候选更新完整验证后以临时文件+rename保存成功，才更新内存和广播；写盘失败关闭连接，
不广播未提交的内容。数据目录保存 Yjs 二进制状态，不包含身份令牌，不能提交到仓库。

当前持久化属于本机协作文档；服务同时保存云端基准版本与协作状态，
这份检查点不等同于用户可浏览的保存历史。
缺少本地房间文件时，服务使用当前已验证用户的身份从云端读取图表，经有界读取、
内容清洗和公开 SDK 转换后，先持久化再开始同步；查看者也可以先进入。
并发首次进入共用一次初始化。空云端图也会保存权威的空状态，阻止旧客户端内容回填。
读取、转换或首次写盘失败时拒绝连接，不同步部分内容。
已有房间进入时会读取云端基准，在线房间也会监测云端版本变化。
服务用共同基准、当前协作状态和新云端内容进行三方合并；
可合并的变化持久化后再同步，无法确定的旧房间或同字段冲突会暂停协作，
避免直接覆盖未保存内容。冲突时所有者可选择“从云端恢复并重连”；
确认后先提交独立本地副本，再恢复已确认的云端版本。其他成员在线时服务拒绝恢复，
需要各成员先离开房间。恢复不删除本地副本或服务器上的原始文件备份。
文件存储已提供内部恢复原语：先按当前文件SHA-256确认，保存并重新校验原始文件备份，
再次检查源文件未变后原子替换为已验证的检查点。损坏和空文件也会完整保留在备份中。
同一存储实例的恢复与普通保存共用写入队列；排队前捕获替换快照，失败不会阻塞后续写入。
HTTP恢复边界已接入服务入口。界面提供显式确认，在当前画布的独立本地副本完成IndexedDB事务并读回校验后才提交恢复。
恢复期间冻结画布，接受远端画布成功后才解锁；图表/身份变化取消旧请求。副本失败不提交恢复，已保存副本在服务失败后保留。
仅接受已配置Origin和Bearer身份；
真实所有者按diagrams.user_id校验，协作者中的owner标签不授予恢复权限。
GET `/recovery/vizly-room-<UUID>` 仅返回文件摘要、字节数和云端版本；
POST同地址只接受确认的sha256及revision，不接受客户端替换内容。
服务重新读取云端内容、核对新版本并复验所有权；房间有在线成员、正在接入的连接或其他恢复时拒绝操作。
新WebSocket连接在恢复期间被拒绝；截止、断开或关闭服务会取消尚未提交的准备，并释放独占预约。
请求体预算1024字节，待处理鉴权最多16个；响应和日志不含凭证或图表内容。
文件摘要不代表授权。此存储队列只约束单实例写入，不能作为多进程或断电持久性验证。
协议消息6将已接受的云端版本与文档状态向量配对，客户端收到相应状态后才更新版本。
转换入口必须使用支持 Node 无 DOM 初始化及 NodeNext 类型声明的本地 Core 包。
正式上线前还需验证双浏览器实际画布、并发编辑、过期令牌、撤权、重启恢复、
云端保存和生产WSS/持久卷/备份，不能用协议测试代替这些验收。

`npm run test:e2e` 包含独立的恢复浏览器门禁。它使用合成登录身份、截获的云端/协作响应，
通过真实公开SDK和IndexedDB验证编辑副本、恢复顺序、失败保留及重新打开；
构建输出为 `dist/recovery-fixture`，不覆盖主预览文件。可单独运行
`npx playwright test --config playwright.recovery.config.ts`。此门禁不替代真实双账号验收。
